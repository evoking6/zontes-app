```text

```

## 3. 当前确认的加密与传输事实

原厂 RSA 工具 `a.nie` 在运行时恢复后的实现使用：

```text
KeyFactory: RSA
公钥输入: Base64(X.509 SubjectPublicKeyInfo DER)
Cipher: RSA/ECB/PKCS1Padding
```

使用合成明文和独立的 2048 位测试公钥调用该原函数，输出为 256 字节。**这验证了这个工具的行为，没有证明其调用方就是车辆控车入口，也没有确定当前控车公钥。** App 内其他 SDK 的 RSA 授权密钥不能混用。

当前样本仍包含 `*UF`、`*ULoc`、`*UClear`、`*UL,` 等前缀。前缀的存在不能证明完整字段、时间块、Nonce 编码、认证材料、外层加密和回执关联规则均未变化。

App 同时包含消息、文件及 Socket 业务。类名 `SocketService`、端口或共享前缀均不足以单独确认控车路径；必须核对控车界面到实际发送函数的完整调用链。

按顺序完成：确认原厂样本 → 恢复实际调用 → 记录脱敏固定样例 → 独立实现逐字节对照 → 当前服务认证与只读验证 → 用户验收一次动作。各阶段分别记录证据，禁止用离线算法向量替代车辆响应。
